# Physics and chemistry in Entail

Mathematics had a law, and Python did not. These two subjects sit closer to mathematics:
each has a law that fixes the answer, once a request is written in the subject's own
notation. This page records what the programs do, how they scored, and where they stop.

| Program | Reads | Writes |
|---|---|---|
| [`physics.entail.txt`](../scripts/entail/physics.entail.txt) | `12 kg * 3 m/s^2 =` | `36 N` |
| | `3 km + 200 m =` | `3200 m` |
| | `3 m + 2 s =` | `incompatible units` |
| [`chemistry.entail.txt`](../scripts/entail/chemistry.entail.txt) | `M(C6H12O6)=` | `180.156 g/mol` |
| | `The molar mass of Ca(OH)2 is` | `74.094 g/mol` |
| | `2H2 + O2 -> 2H2O is` | `balanced` |

## The idea in each

**Physics is the algebra of units.** The program lists no laws. A unit is a vector of
exponents over kg, m, s, A, K and mol, plus a power of ten. Multiplying adds the vectors,
dividing subtracts them, and adding demands that they match. That is all linear, so
Entail can say it directly. `F = ma`, `W = Fd`, `P = VI` and `V = IR` then all follow,
and a sum of metres and seconds is refused in words. The digits are handled as in
`mathematics.entail.txt`.

**Chemistry is a sum over atoms.** Every token adds only what it changes: in `H12`, the
`H` adds one atom and the `2` adds the other eleven. A digit after `)` repeats the bracket.
A balance check compares the total mass of each side, because a reaction can't create any.

`chemistry.entail.txt` is generated by `make_chemistry.py`, because a formula's tokens
depend on the tokenizer. Qwen reads `NaCl` as `Na|Cl` in one place and `(N|a|Cl` in
another, so the table lists 1,699 tokens with what each contributes. The atomic weights
are PubChem's.

## Results

Qwen 3.5 0.8B, on the CPU. Each prompt opens with a short drill so that the base model
answers. Answers were worked out separately in Python, and a reply must open with the
right number and unit.

| Test | Cases | Base | Graft |
|---|---|---|---|
| Molar mass, as `M(X)=` | 71 | 40 | 71 |
| Molar mass, as a sentence | 71 | 44 | 71 |
| Balanced equations | 20 | 20 | 20 |
| Unbalanced equations | 20 | 0 | 20 |
| Laws, multiplying | 54 | 4 | 54 |
| Laws, dividing | 42 | 5 | 42 |
| Prefixed units | 36 | 0 | 32 |
| Sums and differences | 48 | 3 | 48 |
| Mismatched units refused | 16 | 0 | 16 |

The base model says `balanced` to every equation, so its 20 of 20 means nothing. Its
physics score is strict: a quotient must match to the last digit, and the program
truncates. Allowing 1% with the right unit, the base model scores 39 of the 180 numeric
physics cases, and it names the right unit on 58.

The graft broke no answer the base model had right. The 4 prefix misses are all `mV`,
which Qwen splits into ` m` and `V`: the program stays silent, and the host answers
wrongly. On 11 requests outside either program's range, both stayed silent.

Loss on prose moved from 3.55195 to 3.55203 nats per token for chemistry and 3.55206 for
physics. The graft is 53 layers for chemistry and 70 for physics, against 24 for the host.

Two further sets were written after the programs were finished and scored through
`entail run` with Qwen's tokenizer, without weights: chemistry 70 of 70 on new compounds
and equations, and physics 192 of 196 on new numbers, with the same 4 `mV` misses.

## What this doesn't do

**Neither program changed a single chat reply.** Asked in plain English, over 10 questions
each, the graft and the base model gave identical answers. Qwen writes its working in
LaTeX, as `12 \text{ kg} \times 3 \text{ m/s}^2`, which neither program can read. The same
gap appeared for mathematics on a smaller scale. A program acts on notation it knows, so
reaching chat needs either a reader for LaTeX or a host that writes plain expressions.

The rest are limits of scope:

- **Physics** takes one operation between two quantities. It has no hours, minutes or
  degrees Celsius, doesn't convert between units on request, and doesn't read ` ohm`,
  which is split into two tokens. A quotient is truncated, with no significant figures.
- **Chemistry** takes one level of brackets, one-digit coefficients and four species a
  side. Its first species needs a new line or `:` in front.
- **The balance check compares mass,** not each element, so it would pass an equation
  that swapped elements of exactly equal weight.
- **Neither sets up a problem.** Like the arithmetic, each gives the exact answer to what
  was written, so the wrong formula gets a correct answer to the wrong question.

## What was learned

**Look for the algebra behind a subject.** Listing physics laws one by one would have been
long and brittle. The unit vector is 7 numbers and covers them all.

**Let each token say what it changes.** Both programs avoid parsing by making a quantity
a sum of per-token contributions, so depth stays low: 27 layers for chemistry.

**A refusal can be an answer.** `incompatible units` is the first case where a program
says no in words, which [entail-synthesis.md](entail-synthesis.md) lists as a gap.

**A graft holds less than the interpreter.** `entail run` uses doubles, while a host's
embedding is bf16 and rounds a mass such as 15.999. Masses now arrive in parts of at
most 256. Reading the code found this before a test did, so test the weights as well.

**Check what the scorer punishes.** Two apparent failures were the test's fault: a token
limit that cut off `kg/m^3`, and a host that added a full stop after a right answer.

## Reproducing it

```bash
python scripts/entail/make_chemistry.py <periodic-table.csv> <tokenizer.json> scripts/entail/chemistry.entail.txt
```

```bash
python scripts/entail/science_cases.py physics cases.jsonl 7
```

```bash
amql-cli entail run scripts/entail/physics.entail.txt --tokenizer <dir> --cases cases.jsonl --report replies.json
```

```bash
python scripts/entail/science_cases.py score cases.jsonl replies.json
```

Graft and evaluate as in [entail-synthesis.md](entail-synthesis.md), then pass the base
model's report to `score` with `--base`.
